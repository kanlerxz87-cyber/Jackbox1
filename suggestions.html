Review protocol

  1. Read the suggestion's 'unblocks' list. If none of those questions is blocking, the suggestion is not urgent.
  2. Read the 'falsifier'. If it is likely to be true, the suggestion buys little.
  3. Check 'stays_private'. Any suggestion that would put an identifier on the public site is rejected outright, regardless of benefit.
  4. Choose at most three to start. Record the choice, the date and the owner in COORDINATION.md so parallel sessions do not duplicate the work.
  5. Revisit the register when a blocker closes, because the ranking changes when the facts change.

One suggestion that was deliberately declined

Do not build the versioned cash-flow model yet — S-16

The brief asks for a versioned, back-tested cash-flow model once verified inputs and sufficient comparable history exist. The condition in that instruction is doing real work. There are currently no verified inputs and no comparable history, so a model built today would be a spreadsheet fitted to nothing, carrying a version number that implies rigour it does not have. The four-scenario calculator on the Sell vs Renew page is the honest interim tool: it makes every assumption visible and refuses to store one as a fact.

When to revisit: after S-05 produces a dated comparable set with enough history to back-test against. At that point the model has something to be wrong about, which is the only way back-testing means anything.

How to improve this site itself

For decision-making quality

  • Add a single dated status line to every gate, so progress is visible over time rather than as a snapshot.
  • Add a comparable-sales evidence table, empty until documents exist, so the shape of the missing evidence is visible rather than abstract.
  • Add a printable one-page brief per adviser, so each receives only the questions they own. (Partially done: see the One-Page Summary.)
  • Add a change log, so a reviewer can see what changed between visits and does not re-read the whole site.

For reviewability

  • Every flag on the Flagged for Review page carries the URL that was attempted, so a reviewer can retry it rather than take the flag on trust.
  • Every value on the Market & Economy page links to the official page it was read from.
  • The Sources page lists every domain used, with what it was used for and what it cannot be used for.
  • Nothing on this site is fetched at runtime. The pages are static, so what you read is what was verified on the compile date shown in the header.
