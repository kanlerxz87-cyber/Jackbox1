Everything that could not be confirmed, published rather than suppressed. Each item records what was attempted, why it failed, what it affects, and what would close it. Nothing on this page is used as a value anywhere on the site.

This page exists so the site can be trusted. A dashboard that shows only what worked is more dangerous than one that shows the gaps. These 14 items do not block publication and they do not block the merge. They block reliance on the specific figure or conclusion named in each row.

Flag categories

  • source unavailable — The official page existed but did not return usable content to this reader.
  • not published officially — The figure exists in practice but no official published page carries it.
  • identifies parcel — The official source can answer the question, but only by keying off the private address, so the answer is deliberately withheld from the public product.
  • data gap official — The statistical agency itself has a gap in its series.
  • repo irregularity — Something about the repository or the environment that a reviewer should know.

What this means for a reader

If a row here names a figure you were about to rely on, do not rely on it. Open the attempted URL in a browser: several of these failures are reader-specific, and the page may work for you. If it does, record the value with the date you read it and update the data file.

If a row here names a conclusion, treat that conclusion as withheld rather than as negative. For example, the absence of a parcel hazard designation on this site does not mean the parcel is free of hazard; it means the designation is private.

How to request a change

  1. Open the attempted URL and confirm the value with its period and vintage.
  2. Edit the matching entry in data/market.json, data/hazards.json or data/flagged.json.
  3. Set verified to true and paste the exact URL you read it from.
  4. Remove the item from flagged.json only if it is fully resolved, and note the resolution in the commit message.
  5. Rebuild with python3 tools/build_site.py and confirm the row now shows a source and no warning badge.
